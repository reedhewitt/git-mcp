# git-mcp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single small Zig binary that speaks MCP over stdio and exposes safe, non-interactive git operations to a sandboxed agent, running the user's own `git` on the host.

**Architecture:** `main.zig` reads newline-delimited JSON-RPC from stdin, one request at a time, using a per-request arena. `mcp.zig` dispatches the protocol methods. Tools come from a declarative table (`tools/registry.zig`): each tool has a name, a description, a JSON-schema string literal, and a handler. Handlers validate their arguments (`validate.zig`, `tools/Args.zig`) and then run git through `git.zig`. That runner spawns git in its own process group, with a fixed non-interactive environment, an absolute deadline, and capped output capture.

**Tech Stack:** Zig 0.17.0, standard library only. Uses the system `git`.

**Spec:** `docs/superpowers/specs/2026-10-27-git-mcp-design.md`. Read it before starting any task. The anti-goals in the spec are hard requirements.

## Global Constraints

- Zig `0.17.0`, std only; `build.zig.zon` `.minimum_zig_version = "0.17.0"`, no `.dependencies`.
- `main` signature: `pub fn main(init: std.process.Init) !void`. Use `init.io`, `init.gpa`, `init.environ_map`.
- Release build `zig build -Doptimize=ReleaseSmall` should produce a binary well under 1 MB.
- stdout carries only JSON-RPC messages, one per line. All diagnostics go to stderr.
- Requests are processed **sequentially**. There's no concurrency.
- Child git processes never inherit the server's stdio. Always use `stdin = .ignore`, `stdout = .pipe`, `stderr = .pipe`.
- Every git invocation is prefixed with `git --no-pager -c core.quotepath=false -c color.ui=never` and runs with these set: `GIT_TERMINAL_PROMPT=0`, `GIT_EDITOR=true`, `GIT_SEQUENCE_EDITOR=true`, `GIT_PAGER=cat`, `GIT_MERGE_AUTOEDIT=no`. The rest of the environment passes through untouched.
- For network ops only, set `GIT_SSH_COMMAND="ssh -o BatchMode=yes"`, but only if neither `GIT_SSH_COMMAND` nor `GIT_SSH` is in the environment and `git config --get core.sshCommand` (run in the cwd) prints nothing.
- Timeouts: local ops `30_000` ms, network ops (`fetch`, `pull`, `push`, `clone`) `120_000` ms. Each is an absolute deadline for the whole invocation.
- Output: keep at most `1 MiB` per stream from git. Keep reading and discard anything past that. Text returned to the agent is capped at `100 * 1024` bytes on a UTF-8 boundary, with the truncation note `\n… [output truncated at 100 KiB; narrow the request with paths, max_count, or stat_only]`.
- All text sent in JSON must be valid UTF-8. Replace invalid bytes with U+FFFD (`std.json.Stringify` hits `unreachable` on invalid UTF-8).
- Agent-supplied refs, branch, tag, and remote names, and URLs may not begin with `-`. Pathspecs always follow `--`. Messages are passed as `--message=<text>`.
- Nothing personal goes in the repo: no real usernames, home paths, hosts, or remotes. Tests use `Test <test@example.com>`. Docs use placeholders like `/path/to/git-mcp`.
- Commit after each task, ending messages with the session's attribution lines.

## Review Focus

1. **The repo path contains spaces** (`/Users/x/My Notes/kb`): every tool works. Covered by Task 3 (`status works with spaces in path`).
2. **A brand-new repo with no commits yet**: `git_status`, `git_log`, and `git_unstage` return git's message as a normal result or `isError`, and never crash. Covered by Task 5 (`log on unborn branch is an error result, not a crash`) and Task 6 (`unstage in repo with no commits`).
3. **Huge or binary output** (a diff of a 5 MB file, or a commit message in Latin-1): the server truncates and sanitizes the output, and the response is valid JSON. Covered by Task 2 (`caps captured output`), Task 1 (`sanitizeUtf8`), and Task 5 (`diff of huge file is truncated, response valid`).
4. **A grandchild holds stderr open after git exits** (an ssh ControlPersist master or a hook that backgrounds a process): the server returns when git exits instead of waiting for the timeout. Covered by Task 2 (`returns promptly when grandchild keeps stderr open`).
5. **Pushing from a detached HEAD**, or with `branch` omitted and no upstream: the server returns a clear error naming what to pass, and never pushes something unexpected. Covered by Task 4 (`push from detached HEAD without branch fails clearly`).

**Interfaces:**
- Produces:
  - `text.sanitizeUtf8(arena: Allocator, bytes: []const u8) ![]const u8`: returns the input unchanged when it's valid UTF-8. Otherwise returns a copy with each invalid byte replaced by U+FFFD.
  - `text.truncate(s: []const u8, cap: usize) struct { text: []const u8, truncated: bool }`: cuts at or below `cap` on a UTF-8 codepoint boundary.
  - `validate.Diag = struct { msg: []const u8 = "" }`
  - `validate.Error = error{ Invalid, OutOfMemory }`
  - `validate.resolveRepo(arena, io: Io, home: ?[]const u8, raw: []const u8, diag: *Diag) Error![]const u8`
  - `validate.resolveTarget(arena, io, home, raw, diag) Error![]const u8`: for clone and init. The target may not exist, but its parent directory must.
  - `validate.checkName(kind: []const u8, value: []const u8, diag: *Diag) Error!void`
  - `validate.checkPushBranch(value: []const u8, diag: *Diag) Error!void`
  - `validate.checkPath(value: []const u8, diag: *Diag) Error!void`
  - `validate.checkUrl(value: []const u8, diag: *Diag) Error!void`

Rules:
- **`resolveRepo`**:
  - Expand `~` and `~/…` using `home`. If `home` is null, `Invalid` with "HOME is not set; pass an absolute path".
  - Relative paths are `Invalid`, with a message that includes "absolute host path".
  - A non-existent path, or one that isn't a directory, is `Invalid`. The message says this server runs on the host and needs the host path. If the path starts with `/sessions/`, add: "This looks like a sandbox mount path. Use the folder's real path on the host machine (for example /Users/<name>/…)."
  - Strip any trailing `/` except on `/` itself.
- **`checkName`**: rejects empty values, values starting with `-`, and values containing control characters (< 0x20, 0x7f). The message names `kind`, for example "branch name must not start with '-'".
- **`checkPushBranch`**: applies `checkName`, then also rejects a leading `+` and any `:`. The message says "force pushes and remote deletions are not supported; run them in a terminal".
- **`checkPath`**: rejects empty values and NUL bytes.
- **`checkUrl`**: applies `checkName` rules with kind `"url"`.

**Runner implementation decisions:**
- Use `std.process.spawn`, not `std.process.run`:
  - `run` returns `StreamTooLong` and discards output.
  - Its timeout is per-`fill` (idle), not absolute.
  - It kills only git and leaves ssh running.
- Spawn with `.pgid = 0` (new process group), `.stdin = .ignore`, `.stdout = .pipe`, `.stderr = .pipe`, `.environ_map` = base env clone plus the Global Constraints vars, and `.cwd = .{ .path = opts.cwd }`.
- Compute one deadline up front with `Io.Timeout.toDeadline`. Read both pipes with `Io.File.MultiReader`, calling `fill` in **250 ms slices** until EOF on both pipes or the deadline. Once a stream's buffered data exceeds `capture_cap`, copy the bytes you're keeping and discard the rest, so git never blocks on a full pipe. Set `truncated`.
- Between slices, poll whether git has exited (`std.posix.waitpid(pid, WNOHANG)` or the 0.17 equivalent; don't call `child.wait` after reaping by hand). Once git has exited, do one final ≤250 ms drain and stop, even if a grandchild still holds the pipes.
- On the deadline: send `SIGKILL` to the group (`std.posix.kill(-pid, .KILL)`), reap, and return `timed_out = true`, `exit_code = null`, with the partial stdout and stderr.

**Decisions:**
- **`formatResult`:**
  - exit 0: the result is stdout. If stderr isn't empty, append `"\n[stderr]\n" ++ stderr`. If both are empty, the result is `"OK (no output)"`.
  - nonzero exit: `is_error = true`, with the text `"git exited with code {d}\n" ++ stderr ++ stdout`.
  - timeout: `is_error = true`, with the text `"git timed out after {d}s and was stopped\n" ++ partial output`.
  - Always run `sanitizeUtf8`, then `truncate(output_cap)` and append the Global Constraints note when truncated (or when `r.truncated`).
- **Dispatch:**
  - `tools/call` finds the tool by name and builds `Ctx` and `Args`, then calls the handler.
  - `error.Invalid` becomes `ToolResult{ .text = diag.msg, .is_error = true }`.
  - Any other error becomes `is_error` with `"internal error: {s}"` (`@errorName`).
- **JSON-RPC:**
  - Echo `id` verbatim, whether string or number.
  - Messages with no `id` are notifications and get no response, including `notifications/initialized`.
  - Unparseable JSON → `-32700`, `id: null`.
  - Not an object (arrays included), or `jsonrpc != "2.0"`, or no string `method` → `-32600`.
  - Unknown method → `-32601`.
  - `tools/call` with a missing `name`, an unknown tool, or `arguments` that isn't an object → `-32602`.
- **`initialize`:** if the client's `protocolVersion` is in `protocol_versions`, echo it. Otherwise return `protocol_versions[0]`. The result has `capabilities: {tools: {listChanged: false}}`, `serverInfo: {name, version}`, and `instructions`. The `instructions` text: "Runs git on the host machine. Always pass the repository's absolute HOST path (not a sandbox mount path such as /sessions/…/mnt/…). Destructive operations (force push, reset --hard, clean, branch -D, stash drop, discarding uncommitted changes) are intentionally unavailable."
- **`ping`** → `{}`. **`tools/list`** → `{tools:[{name, description, inputSchema}]}`. Parse each `schema` string with `std.json.parseFromSliceLeaky` into the arena.
- **`main.zig`:**
  - Create the Runner from `init.environ_map`. Use `GIT_MCP_GIT` for `git_exe` when set.
  - On macOS, if `SSH_AUTH_SOCK` is missing, run `launchctl getenv SSH_AUTH_SOCK` once and put the result into the child env map if it's non-empty. This is my call: GUI-launched hosts may not pass it through.
  - `home` comes from `HOME`.
  - At startup, log one line to stderr: `git-mcp 0.1.0 git=<git_exe> PATH=<set|unset> SSH_AUTH_SOCK=<set|unset|from launchctl>`. Log only whether each is present, never the values.
  - Read stdin with a 1 MiB buffer and `takeDelimiter('\n')`. Strip a trailing `\r` and skip blank lines.
  - On `StreamTooLong`, write a `-32700` error with `id: null` and `discardDelimiterInclusive('\n')`, then keep serving.
  - Use one `ArenaAllocator` and `reset(.retain_capacity)` after each message. Write the response plus `\n` and flush.
  - Exit 0 on EOF.
- **`git_status`:** schema `{repo}`, plus an optional `"untracked": {"type":"boolean"}` (default true; false → `-uno`). Run `git status` (long format; it already reports branch, ahead/behind, and in-progress merge or rebase with hints).
- **`build.zig`:** add a test module rooted at `tests/e2e.zig` with build options from `b.addOptions()`, using `options.addOptionPath("exe_path", exe.getEmittedBin())`, imported as `build_options`. The `test` step depends on it.

**Tool rules** (network = true for fetch, pull, push, clone):
- **`git_fetch`** `{repo, remote?, all?, prune?, tags?}` → `fetch [--all] [--prune] [--tags] [remote]`
- **`git_pull`** `{repo, remote?, branch?, rebase?: bool, ff_only?}` → `pull [--rebase|--no-rebase] [--ff-only] [remote [branch]]`. A `branch` without a `remote` is `Invalid`.
- **`git_push`** `{repo, remote?, branch?, set_upstream?, tags?}`:
  1. `branch` defaults to `symbolic-ref --short -q HEAD`. Detached HEAD with no `branch` → `Invalid`: "HEAD is detached; pass 'branch' explicitly".
  2. `remote` defaults to `config --get branch.<b>.remote`, else `origin`.
  3. The destination is `config --get branch.<b>.merge` with `refs/heads/` stripped, but only if the upstream remote equals `remote`. Otherwise it's `<b>`.
  4. Run `checkPushBranch` on both the source and the destination. Run `checkName("remote", …)`.
  5. If `config --type=bool --get remote.<r>.mirror` prints `true` → `Invalid`: "remote '<r>' is configured as a mirror; pushing to it is not supported".
  6. Run `push [-u] [--tags] <remote> refs/heads/<b>:refs/heads/<dst>`.
- **`git_clone`** `{url, directory, branch?, depth?}`:
  - `checkUrl`, `resolveTarget`
  - cwd = the parent of `directory`
  - `clone [--branch <b>] [--depth <n>] -- <url> <directory>`. A `depth` < 1 is `Invalid`.
- **`git_init`** `{directory, initial_branch?}` → `resolveTarget`, `init [-b <name>] -- <directory>`
- **`git_remote`** `{repo, action: list|add|set_url|rename, name?, url?, new_name?}`:
  - `list` → `remote -v`
  - `add` → `remote add <name> <url>`
  - `set_url` → `remote set-url <name> <url>`
  - `rename` → `remote rename <name> <new_name>`
  - There is no remove action.

Each description says when to use the tool. `git_push`'s description says it never force-pushes and that rejected non-fast-forward pushes must be resolved with `git_pull`.
